# Concentrate — 設計ドキュメント

> タスクに集中するための macOS アプリ。集中セッション中は、いま開いているアプリ/フルスクリーンから移動できないようにロックする。

最終更新: 2026-06-09

---

## 1. 目的とコンセプト

ユーザが「集中したい」と思ったとき、ワンアクションで一定時間のロックをかけ、その間は ⌘Tab・スペース切替・トラックパッドスワイプなどでの**他アプリ/他スペースへの移動を不可能にする**。解除は **時間経過** または **パスコード入力** のみ。

設計思想は **「友好的な摩擦(friendly friction)」**。完全な脱出不能(監獄)は目指さない。本気で抜けようとすれば抜けられるが、十分に面倒で「やっぱり集中しよう」と思わせる心理的障壁を作ることがゴール。これは [§9 既知の限界](#9-既知の限界とリスク) の技術的制約とも整合する。

---

## 2. スコープ

### 対象(In Scope)
- macOS ネイティブアプリ(Apple Silicon / Intel)。対象 OS は macOS 14 (Sonoma) 以降を想定。
- メニューバー常駐 + ポップオーバー UI からの集中セッション開始/解除。
- 集中セッション中のキーボード経由の移動経路ブロック(⌘Tab、⌃矢印、Mission Control など)。
- セッション中のトラックパッド「フルスクリーンアプリ間スワイプ」の一時無効化と終了時復元。
- タイマー解除 / パスコード解除。

### 非対象(Out of Scope, 初期版)
- Windows / Linux 対応。
- Web サイト/特定アプリのブロック(ネットワークフィルタ型の集中アプリ機能)。
- 強制終了・再起動・SSH 等までを塞ぐ徹底ロック(→ [§9](#9-既知の限界とリスク))。
- 統計/レポート、クラウド同期、複数デバイス連携。
- Raycast/Alfred 連携(将来検討。本体は常駐させる前提で拡張可能な作りにはしておく)。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 集中セッション | ロックが有効な期間。開始〜解除まで。 |
| ロック | 移動経路ブロックが有効な状態。 |
| 脱出経路 | ⌘Tab やスワイプなど、ユーザが他アプリ/他スペースへ移れる手段。 |
| イベントタップ | `CGEvent.tap`。キーボード/マウス/ジェスチャイベントを横取り・握り潰す仕組み。 |
| 握り潰す(swallow) | イベントタップのコールバックで `nil` を返し、イベントをシステムに伝播させないこと。 |

## 4. ユーザ体験(UX フロー)

```
[メニューバーアイコン] --クリック/ホットキー--> [ポップオーバー]
   ポップオーバー:
     - 集中時間の選択 (例: 15 / 25 / 50 分 / カスタム)
     - [集中開始] ボタン
     - (設定: パスコード, ホットキー, スワイプ無効化ON/OFF)
          |
          v  [集中開始]
   [ロック中]
     - メニューバーアイコンが残り時間を表示
     - 脱出経路はブロックされる
     - 解除手段:
         (a) 残り時間が 0 になる        -> 自動解除
         (b) 解除ホットキー -> パスコード入力パネル -> 一致で解除
          |
          v
   [解除] -> 設定・トラックパッド設定を復元 -> idle に戻る
```

### 画面一覧
1. **メニューバーアイコン**: 状態表示(idle / 残り時間)。クリックでポップオーバー。
2. **メインポップオーバー (NSPopover or NSPanel)**: 時間選択 + 集中開始。
3. **設定ウィンドウ**: パスコード設定、解除ホットキー、スワイプ無効化の有無、起動ホットキー。
4. **パスコード入力パネル (NSPanel, フローティング)**: ロック中に解除ホットキーで最前面表示。
5. **オンボーディング**: 初回起動時に Accessibility / Input Monitoring 権限の案内 + パスコードの初期設定(必須)。

## 5. 機能要件

- FR-1: ユーザは集中時間(分)を指定してセッションを開始できる。
- FR-2: セッション中、以下のキーボード脱出経路を無効化する: ⌘Tab, ⌘`(バッククォート), ⌃←/→, ⌃数字, F3(Mission Control), ⌃↑, ⌘H, ⌘M, ⌘Q。
- FR-2a: 強制終了(⌘⌥Esc / Activity Monitor)は**意図的にブロックしない**。パスコードと並ぶ脱出ハッチとして残す(友好的な摩擦)。
- FR-3: セッション中、トラックパッドの「フルスクリーンアプリ間スワイプ」を無効化し、解除時に元の設定へ復元する(設定でON/OFF可能)。
- FR-4: 残り時間が 0 になったら自動的に解除する。
- FR-5: 解除ホットキーでパスコード入力パネルを表示し、正しいパスコードで即時解除できる。
- FR-6: パスコードは**初回起動時に必須で設定**し、Keychain に安全に保存する。以後は設定画面から変更可能。
- FR-7: イベントタップが無効化された場合に検知して自動再有効化する。
- FR-8: アプリのクラッシュ・終了時にトラックパッド等のシステム設定を確実に復元する(復元漏れ防止)。

## 6. アーキテクチャ

### 6.1 技術スタック
- **言語/UI**: Swift + AppKit(常駐・パネル・イベントタップ)+ SwiftUI(ポップオーバー/設定画面の中身)。
- **常駐形態**: アクセサリアプリ(`LSUIElement = true`、Dock 非表示)。
- **イベント処理**: CoreGraphics `CGEvent.tap`。
- **永続化**: `UserDefaults`(設定)+ Keychain(パスコード)。
- **配布**: Developer ID 署名 + notarize の `.dmg`(App Store 不可、[§8](#8-権限と配布) 参照)。

### 6.2 モジュール構成(案)

```
ConcentrateApp/
├─ App/
│   ├─ AppDelegate.swift          # 常駐起動, ライフサイクル, 異常終了時の復元フック
│   └─ MenuBarController.swift     # NSStatusItem, 残り時間表示, ポップオーバー制御
├─ UI/
│   ├─ FocusPopoverView.swift      # 時間選択 + 開始 (SwiftUI)
│   ├─ SettingsView.swift          # 設定 (SwiftUI)
│   └─ PasscodePanel.swift         # 解除パスコード入力 (NSPanel + SwiftUI)
├─ Core/
│   ├─ SessionController.swift     # 状態機械 (idle/locked/unlocking), タイマー
│   ├─ EventTapBlocker.swift       # CGEventTap 設置/握り潰し/健全性監視
│   ├─ GestureGuard.swift          # トラックパッド設定の退避→無効化→復元
│   ├─ HotKeyManager.swift         # 起動/解除ホットキー (タップ対象外)
│   └─ PasscodeStore.swift         # Keychain 読み書き
└─ Support/
    ├─ Permissions.swift           # Accessibility / Input Monitoring 確認・誘導
    └─ Settings.swift              # UserDefaults ラッパ
```

### 6.3 状態機械

```
            開始(時間指定)
   idle ───────────────────────▶ locked
    ▲                               │
    │  復元完了                      │  解除ホットキー
    │                               ▼
    └──────── unlocking ◀──── (パスコード入力待ち)
       タイマー0 / パスコード一致      │
                                     │ パスコード不一致 / キャンセル
                                     └──▶ locked に戻る
```

- `idle`: 通常状態。タップ未設置。
- `locked`: タップ設置済み + スワイプ無効化済み。メニューバーに残り時間。
- `unlocking`: パスコードパネル表示中(ロックは維持。パネル操作のための最小限の入力のみ許可)。

## 7. ロック技術の詳細

### 7.1 前提:フルスクリーン = 独立 Space
macOS のネイティブフルスクリーンアプリは専用 Space に入る。「そのアプリから移動できない」を実現するには、**他アプリ切替**と**Space 移動**の両方を、キーボード経路・ジェスチャ経路の双方で塞ぐ必要がある。

### 7.2 キーボード経路:CGEventTap
- 設置: `CGEvent.tap(tap: .cgSessionEventTap, place: .headInsertEventTap, options: .defaultTap, eventsOfInterest: keyDown|flagsChanged, callback:)`。
- 握り潰し: コールバックで対象の組合せ(modifier flags + keyCode)を判定し `nil` を返す。
- 対象キーは [§5 FR-2](#5-機能要件) を参照。
- 最前面がどのアプリでも作用するため、「ユーザが開いている別アプリ」に留めさせられる。

#### 健全性監視(重要)
- イベントタップはシステムにより**静かに無効化される**ことがある。`CGEvent.tapIsEnabled(tap:)` を定期(例: 1〜2秒)チェックし、無効なら `CGEvent.tapEnable(tap:enable:true)` で再有効化する。
- 署名・TCC の同一性問題で「タップは作れたのにイベントが来ない」事象があるため、配布時の署名と権限付与フローに注意。

### 7.3 ジェスチャ経路:トラックパッドスワイプ
3/4本指スワイプによる Space 移動は WindowServer がイベントタップより低レイヤで処理するため、タップでの確実な握り潰しは困難。本アプリでは **セッション中だけシステム設定で無効化** する方式を採用(確定方針)。

- 退避: 開始時に現在の「フルスクリーンアプリ間スワイプ」関連設定を読み取り保存。
- 無効化: `defaults` 相当の設定でジェスチャを OFF にし、設定を再読込させる。
- 復元: 解除時(および異常終了時)に元の値へ戻す。
- 注意: 設定の即時反映が不安定な場合があり、機種・OS によっては確実反映に再ログインを要することがある。→ オンボーディングと設定画面で注意喚起。
- フォールバック: 反映が効かない環境向けに、イベントタップでジェスチャ系イベントもベストエフォートで拾う実装を併設してもよい(将来)。

### 7.4 補助:kiosk プレゼンテーションオプション
`NSApplicationPresentationOptions` のキオスク設定(`disableProcessSwitching` 等)は**自アプリがアクティブな間のみ**有効で `hideDock` 系併用が必須。本用途(別アプリに留める)では主役にできないため、あくまで補助。パスコードパネル表示中など自アプリが前面のときのガードに限定して検討する。

## 8. 権限と配布

### 権限
- **Accessibility**(必須): イベントタップでの握り潰しに必要。`AXIsProcessTrustedWithOptions` で確認し、未許可なら System Settings へ誘導。
- **Input Monitoring**(必要な場合あり): キーイベント取得のために要求される構成があるため、両方を案内する前提で設計。
- 権限はユーザが手動で許可する必要があり、サイレント取得は不可。初回オンボーディングで丁寧に誘導する。

### 配布
- **サンドボックス非対応** → **App Store 配布は不可**。
- **Developer ID 署名 + notarize** の `.dmg` / `.app` で外部配布。
- 署名後の再署名は TCC 同一性をリセットしうるため、権限再付与が必要になる点に留意。

## 9. 既知の限界とリスク

公開 API だけでは「完全な監獄」は作れない。確定方針「友好的な摩擦」はこの制約と整合する。

- **塞げない脱出経路**: Activity Monitor からの強制終了、ターミナル/SSH での kill、ログアウト、再起動。これらまで塞ぐにはヘルパー常駐・自動再起動・root 権限などが必要で、侵襲的かつ壊れやすく、SIP の壁もある。初期版では塞がない。
- **イベントタップの不安定性**: システムによる無効化 → 健全性監視で緩和([§7.2](#72-キーボード経路cgeventtap))。
- **トラックパッド設定の反映不安定**: 機種/OS 依存([§7.3](#73-ジェスチャ経路トラックパッドスワイプ))。
- **設定復元漏れ**: クラッシュ時にスワイプ無効化が残るとユーザ環境を壊す。→ FR-8 で、起動時に「前回セッションが異常終了していないか」を検知して復元するセーフガードを必須化。
- **権限剥奪**: ユーザが途中で Accessibility 権限を外すとタップが死ぬ。状態を監視し、ロック維持不能なら安全に idle へ戻して通知。

## 10. 段階的実装計画(マイルストーン)

1. **M0 / PoC(リスク潰し)**: ⌘Tab・⌃矢印を CGEventTap で実際に握り潰せるか最小コードで検証。Accessibility 権限フロー込み。
2. **M1 / 最小ロック**: メニューバー常駐 + 時間選択ポップオーバー + キーボード経路ブロック + タイマー自動解除。
3. **M2 / 解除手段**: 解除ホットキー + パスコードパネル + Keychain 保存。
4. **M3 / スワイプ対策**: トラックパッド設定の退避/無効化/復元 + 異常終了セーフガード。
5. **M4 / 仕上げ**: オンボーディング、設定画面、健全性監視、署名・notarize・配布。

> 確定方針では「設計ドキュメント整備」が最初の成果物。本ドキュメントが M0 着手の前提資料となる。

## 11. 未決事項(要検討)

- 集中時間のプリセット値と上限(例: 最大 4 時間?)。
- 解除ホットキーの既定値(他アプリと衝突しにくいもの)。
- ⌘Q の握り潰しを「全アプリ」にするか「最前面アプリのみ」にするか(全体だと OS の操作感に影響)。※ 強制終了系は FR-2a で対象外に確定。
- 複数ディスプレイ環境での挙動。
- ロック中の通知・集中モード(macOS Focus)連携の有無。

### 解決済みの決定(2026-06-09)
- 強制終了(⌘⌥Esc / Activity Monitor)はブロックしない(FR-2a)。
- パスコードは初回起動時に必須設定(FR-6)。
